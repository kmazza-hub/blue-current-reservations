# V100.2.0 — Consolidated Operator Shell Ownership

## Purpose
End the legacy visibility/classification conflict that caused the Hospitality OS Command shell to alternate between blank/hidden and legacy-styled states.

## Runtime changes
- Product Experience no longer classifies `#blueCurrentCommand` / `.bc-os-shell` as an advanced legacy surface.
- Operator Experience no longer assigns legacy `data-bc-priority` or `bc-deep-tool` ownership to the Hospitality OS shell.
- Operator Usability no longer injects legacy purpose chips into the application shell.
- Hospitality OS explicitly claims shell ownership and removes legacy visibility markers on initialization.
- CSS contains a narrow defensive visibility contract for the canonical shell without exposing unrelated legacy/deep surfaces.

## Preserved
All V100.1.x authentication, bearer transport, auth overlay, Command lifecycle, presentation, connectivity, Kitchen routing, and commercial V100 controls remain preserved.

## Acceptance
1. Command remains visible for at least 60 seconds after startup.
2. No pale legacy `Primary workspace` treatment appears on the shell.
3. No blank-screen transition occurs.
4. Guests, Service, Team, Kitchen and Command navigation all remain usable.
5. Authentication/session state remains stable.

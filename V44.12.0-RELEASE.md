# Blue Current V44.12.0 — Multi-Agent Orchestration

## Scope

This release advances Operation V / V44 AIP from persistent single-agent runtime controls into governed, server-backed multi-agent coordination.

### V44.8 — Multi-Agent Planning
- Converts an existing persistent AIP run into a durable orchestration.
- Decomposes the compiled plan into agent-owned tasks.
- Retains execution mode, approval requirements, dependencies, and shared instruction context.

### V44.9 — Durable Task Delegation & Handoffs
- Persists task ownership and sequential dependencies server-side.
- Records agent-to-agent handoffs as durable artifacts.
- Carries only governed dry-run context between agents.

### V44.10 — Orchestration Lifecycle
- Adds start, advance, checkpoint, pause, resume, recover, complete, and cancel controls.
- Persists orchestration checkpoints separately from persistent agent-run checkpoints.
- Recovery restores task position/status from the latest orchestration checkpoint.

### V44.11 — Human Approval Orchestration
- Approval-gated orchestrations cannot start without an explicit recorded human decision.
- Approval and rejection decisions are audit-recorded.
- Approval scope is explicitly `governed-dry-run-only`.
- Approval never sets `liveExecutionAllowed` to true.

### V44.12 — Coordination Readiness
- Adds readiness checks for multi-agent planning, durable delegation, handoffs, checkpoints, approval orchestration, approval scope, and no-live-mutation safety.

## New APIs
- `GET/POST /api/aip/orchestrations`
- `GET /api/aip/orchestration-context`
- `POST /api/aip/orchestration-control`
- `GET/POST /api/aip/approvals`
- `GET /api/aip/coordination-readiness`

## Safety boundary
This release does not introduce live restaurant mutation. Multi-agent workflows remain `governed-dry-run`; approvals authorize only that dry-run coordination scope.

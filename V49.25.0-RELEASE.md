# BLUE CURRENT V49.25.0 — LAUNCH STABILIZATION

V49.21–V49.25 adds the post-launch stabilization layer between a human-recorded cutover and a location being declared operationally stable.

## Stabilization observation

A location enters stabilization only after a cutover result has been recorded.

Each observation captures:

- observation window
- first-service verification
- API health
- authentication health
- reservation integrity
- floor integrity
- kitchen integrity
- workforce integrity
- severity
- incident/degradation description
- operator note
- timestamp / actor

High or Critical severity requires an incident description.

## Stabilization exit criteria

Blue Current evaluates:

1. Human-recorded cutover succeeded.
2. At least one post-launch observation exists.
3. First service is verified.
4. Latest observation passes all health checks.
5. No critical launch observation exists.
6. Current leadership attention is not High/Critical.
7. At least one clean first-service stabilization observation exists.

## Rollback signal

Blue Current surfaces `REVIEW_ROLLBACK` when launch evidence warrants leadership review, including:

- cutover did not succeed
- critical stabilization observation
- repeated health failures
- current High/Critical leadership attention

This signal is advisory only.

## Human stabilization declaration

Adds:

`POST /api/launch-stabilization/locations/:locationId/declare`

Supported human decisions:

- `STABLE`
- `EXTEND`
- `ROLLBACK`

STABLE with open exit criteria requires a documented executive reason.

ROLLBACK always requires a documented human reason.

A rollback decision is stored as:

- `decision: ROLLBACK`
- `executionState: ROLLBACK_DECIDED_NOT_EXECUTED`

Blue Current does not execute rollback.

## API

GET `/api/launch-stabilization`

POST `/api/launch-stabilization/locations/:locationId/observe`

POST `/api/launch-stabilization/locations/:locationId/declare`

Observations require write/admin permission.

Stabilization declarations require admin permission.

# BLUE CURRENT V46.40.0 — DISPOSABLE RETIREMENT REHEARSAL

## Release scope

V46.36–V46.40 adds the final non-destructive rehearsal layer before any future authoritative code removal.

A proposed retirement is applied only to an isolated temporary repository copy.

### V46.36 — Disposable Repository Copy

The rehearsal service creates an isolated temporary copy of the Blue Current repository.

The authoritative repository is never used as the mutation target.

The temporary copy retains the files needed by the validator, including database migrations and a copied runtime fixture database.

### V46.37 — Simulated Dependency Removal

Inside the disposable copy only, the rehearsal can:
- remove the candidate HTML section
- remove candidate script registrations
- remove candidate module files
- remove the candidate startup-registry registration
- remove dependency references from other startup registrations
- remove known operator rationalization/navigation references

The authoritative source remains untouched.

### V46.38 — Real Rollback Archive + Proposed Change Set

Every rehearsal creates an actual temporary rollback archive in Blue Current rollback JSON format.

The archive contains:
- exact source file paths
- SHA-256 hash per backed-up file
- base64 file content
- archive scope digest

The rehearsal also generates a proposed simulated change-set artifact.

These artifacts are generated in the temporary rehearsal workspace and are not applied to the authoritative repository.

### V46.39 — Disposable Full Validation

The rehearsal runs the real repository validator on the disposable modified copy.

It also performs a startup syntax check.

Readiness is blocked if:
- validation fails
- startup dependencies remain
- candidate-related API usage remains
- operational/non-test inbound references remain

Documentation and test references are reported but do not themselves prevent a rehearsal from proving runtime removal safety.

### V46.40 — Authoritative Integrity Certification

Before and after every rehearsal, Blue Current computes a SHA-256 digest over the authoritative source tree.

A successful rehearsal requires identical:
- source-tree SHA-256
- source-file count

The resulting safety state remains:

- `authoritativeMutation: false`
- `authoritativeSafe: true`
- `codeDeletionAllowed: false`
- `deletionExecuted: false`
- `deleteEndpointPresent: false`
- `tempCopyUsed: true`

A successful rehearsal can reach:

`final-change-set-ready-for-human-review`

This is still not deletion permission.

## New API

- provides no authoritative delete operation

# V68.0.0 — Production Write Integrity & Durable Mutation Finalization

V68 returns Blue Current to backend completion work.

## Problems closed

1. `/api/health` was still reporting `59.0.0`. It now reports the package build dynamically.
2. The JSON request body could be consumed by write middleware and then read a second time by the route handler, producing an empty body. `readJson()` now returns the cached parsed body on repeated access.
3. Resource-version commits occurred after `response.end()`. The originating response could therefore leave before version metadata was durable, and its ETag/resource-version headers could not reliably contain the committed version.
4. Write integrity had no durable operation journal.

## V68 behavior

Every authenticated POST/PUT/PATCH/DELETE that passes the centralized write preparation receives:
- durable mutation operation ID
- idempotency reservation/replay behavior
- optimistic resource-version preflight
- durable `prepared` mutation journal record
- synchronous resource-version finalization for successful writes
- synchronous idempotency finalization
- durable committed/rejected/failed mutation result
- `X-Blue-Current-Operation-Id`
- `X-Blue-Current-Write-Integrity`
- committed `ETag` / `X-Blue-Current-Resource-Version` on the originating successful response

If write-finalization metadata cannot be durably committed after the business mutation, the API returns `503 WRITE_FINALIZATION_FAILED` with the operation ID and tells the client to reconcile before retrying.

## Diagnostics

Authenticated operators/admins can inspect:

`GET /api/system/write-integrity`

The snapshot reports prepared, committed, rejected, failed, stale-prepared, health, and recent operations.

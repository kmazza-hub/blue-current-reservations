# BLUE CURRENT V46.15.0 — OPERATOR CONSOLIDATION + USAGE EVIDENCE

## Release scope

V46.11–V46.15 begins actual operator consolidation without deleting working modules.

### V46.11 — Merged Primary-Surface Summaries
Primary operator surfaces can now aggregate mapped merge-source signals.

Examples:
- Reservation Operations can absorb Reservation Yield summaries.
- Live Floor Operations can absorb Operational Digital Twin signals.
- Kitchen Throughput can absorb Kitchen Operations / Predictive Service signals.
- Labor Deployment can absorb Staff Operations / Workforce Intelligence.
- Guest Recovery can absorb Service Recovery.
- Shift Profit Pulse can absorb Margin Intelligence / Cost Variance.

The consolidation layer uses existing AppState rather than creating duplicate backend services.

### V46.12 — Role-Based Default Navigation
Adds reversible default navigation models for:
- Manager
- Executive
- Technical / platform operator

Manager defaults remain the 12 primary shift surfaces.
Executive defaults emphasize performance/profit/portfolio.
Technical defaults emphasize platform/rationalization/runtime surfaces.

Full Platform remains available as a fallback.

### V46.13 — Duplicate Entry-Point Consolidation
Navigation policy is now explicit:

`merge-entry-points-into-primary-targets`

The goal is to route operators through primary surfaces while retaining merged modules underneath until the consolidation is proven.

### V46.14 — Operator-Use Evidence
Adds non-destructive operator-use evidence captured in AppState when a consolidated surface is opened.

Evidence records:
- surface ID
- action
- active role
- timestamp
- source metadata

No restaurant state is changed.

### V46.15 — Evidence-Backed Deprecation Recommendations
Deprecation candidates now receive evidence recommendations:
- `evidence-needed`
- `retain-until-more-evidence`
- `retain-active-use`

The governing policy is:

`merge-before-delete-and-require-use-evidence`

No module is automatically removed.

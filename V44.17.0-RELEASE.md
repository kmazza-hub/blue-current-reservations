# Blue Current V44.17.0 — Durable Versioned Workflow Runtime

## Scope

This release advances V44 AIP from durable multi-agent orchestration into versioned, long-running workflow execution infrastructure.

### V44.13 — Workflow Definition Registry
- Publishes an orchestration as an immutable governed workflow definition.
- Captures task/agent blueprint, approval characteristics, execution mode, and a SHA-256 content hash.

### V44.14 — Workflow Versioning
- Groups definitions into durable lineages.
- Publishes monotonically increasing immutable versions without rewriting prior versions.

### V44.15 — Long-Running Workflow Runtime
- Creates persistent workflow instances pinned to a specific definition version.
- Adds five-minute runtime leases with heartbeat renewal so ownership is explicit.
- Expired leases move running work toward stale/recovery semantics rather than silently continuing.

### V44.16 — Execution Journal + Recovery
- Adds version-bound checkpoints and recovery.
- Adds persistent execution journal entries for lifecycle operations.
- Supports operation keys so repeated advancement requests replay safely instead of completing a task twice.

### V44.17 — Durable Workflow Readiness
- Certifies immutable definitions, version lineages, workflow instances, leases, checkpoints, replayable history, and no-live-mutation boundaries.

## New APIs
- `GET/POST /api/aip/workflow-definitions`
- `GET/POST /api/aip/workflow-instances`
- `POST /api/aip/workflow-control`
- `GET /api/aip/workflow-history`
- `GET /api/aip/workflow-readiness`

## Safety boundary
All durable workflow definitions, instances, checkpoints, and journal entries remain `governed-dry-run`. This release does not authorize live restaurant mutation.

# BLUE CURRENT V51.20.0 — DATA INTEGRITY & RECOVERY

V51.16–V51.20 adds the data-integrity and recovery certification layer required before restaurant pilot use.

## Integrity scope

Blue Current now evaluates the authoritative restaurant data model for:

- reservations
- guest profiles
- floor tables
- floor sections
- staff
- employees
- kitchen stations

Each collection is checked for:

- duplicate entity IDs
- malformed records missing identity/organization scope

No duplicate or malformed record is converted into a pass.

## Persistence / retry / reconciliation verification

The verification workflow reuses existing Blue Current infrastructure:

- DatabaseService durable temp-file persistence and replace/fallback behavior
- database reload support
- IdempotencyService
- SyncReconciliationService

A controlled verification checks:

- entity integrity
- duplicate prevention
- idempotency reservation reuse
- persistence across database reload
- reconciliation state readability

The verification record also captures the existing interrupted-write recovery model.

## Human evidence and certification

Verification requires human-recorded evidence.

Final integrity/recovery certification requires:

- a passing verification
- admin permission
- a human certification note

Certified state:

`DATA_INTEGRITY_RECOVERY_CERTIFIED`

## Important separation

The verification may create integrity-test metadata such as a temporary idempotency record in the isolated/target database, but it does not mutate restaurant reservation, floor, staff, guest, or kitchen operating state.

It does not automatically repair data.

It does not automatically reconcile divergent clients.

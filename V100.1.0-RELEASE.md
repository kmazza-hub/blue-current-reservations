# Blue Current V100.1.0 — Operator Shell Stabilization

This is a surgical operational-hardening package applied on top of the immutable V100.0.0 Commercial V1 baseline. It does not begin a new feature sequence and does not change the package baseline version.

## Repairs

- Makes the authoritative `BlueCurrentAuthSession` coordinator the primary Command authentication signal and synchronizes `appState` from the valid session.
- Waits for auth restoration rather than allowing a stale client state to declare a valid session signed out.
- Corrects the primary Kitchen workspace mapping from Service Coordination to `kitchenThroughputCenter`.
- Promotes Kitchen Throughput as an explicit operator workspace while continuing to hide unrelated legacy/development surfaces.
- Makes quick jobs activate their canonical operator workspace before scrolling to a target.
- Removes false-positive success feedback: a workflow now reports success only if the destination is actually visible.
- Exposes a small `BlueCurrentHospitalityShell` activation API so canonical workflow navigation uses one routing source.

## Deliberately unchanged

- Server authentication and RBAC
- API contracts
- Persistence/database
- Host Stand reservation/waitlist durability
- Service/Kitchen data-source logic
- V100 commercial certification/governance

## Acceptance gates

1. `npm run check`
2. V100 Commercial V1 certification remains green.
3. V100.1 operator-shell stabilization regression test passes.
4. Clean server startup and `/api/health` HTTP 200.
5. Manual browser verification: sign in, reload recovery, Command → Guests → Service → Team → Kitchen → Command, and Service/quick-action → Kitchen Pressure.

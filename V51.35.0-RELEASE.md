# BLUE CURRENT V51.35.0 — RESERVATION & GUEST JOURNEY CERTIFICATION

V51.31–V51.35 certifies the complete guest journey across Blue Current's existing reservation, floor, waitlist, guest-intelligence, and recovery capabilities.

## Ordered journey

1. INQUIRY_AVAILABILITY
2. RESERVATION
3. CONFIRMATION
4. MODIFICATION_CANCELLATION
5. ARRIVAL_WAITLIST
6. SEATING
7. GUEST_CONTEXT
8. GUEST_RECOVERY
9. HISTORY_CONTINUITY

The stage order is enforced.

## System evidence versus human proof

Blue Current now separates:

- supporting system evidence
- human checkpoint evidence
- final human certification

A stage can have real system evidence without being certified.

A human can rehearse an evidence gap only with a documented override reason.

No missing event/history is silently converted into a pass.

## Existing workflows are reused

V51.35 does not create parallel reservation or floor operations.

It reads and certifies continuity from the existing:

- ReservationService
- ReservationOperationsService
- FloorService
- waitlist / seating events
- GuestIntelligenceService
- guest recovery engagements

Journey certification itself does not create, modify, cancel, seat, or contact a guest.

## Stage evidence

### Inquiry / availability
- table inventory
- reservation context

### Reservation
- authoritative reservation record

### Confirmation
- confirmed reservation state

### Modification / cancellation
- reservation update event or cancelled reservation state

### Arrival / waitlist
- arrived reservation or waitlist evidence

### Seating
- seated reservation, seating event, or seated table context

### Guest context
- notes
- VIP state
- accessibility
- derived guest profile context

### Guest recovery
- existing recovery-completed engagement

### History continuity
- reservation event history or repeat guest-key evidence

## Controlled rehearsal

A location can start:

`CONTROLLED_GUEST_JOURNEY_REHEARSAL`

Every completed checkpoint records:

- actor
- timestamp
- human evidence
- system-evidence state
- system check snapshot
- override state/reason
- `reservationMutationPerformed: false`
- `guestContactPerformed: false`

## Human certification

Final state:

`RESERVATION_GUEST_JOURNEY_CERTIFIED`

Certification requires all nine ordered human checkpoints plus:

- human end-to-end evidence
- human certification note
- admin permission

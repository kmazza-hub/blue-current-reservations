# V78.50.1 — Command Authentication Startup Race Hotfix

This hotfix is built directly from the uploaded V78.50.0 repository.

## Root cause

The browser network trace showed:
- `/api/command/operating-picture` -> 401
- `/api/auth/me` -> 200
- `/api/bootstrap` -> 200

That means Command was issuing its protected GET before asynchronous authentication restoration had completed. It then cached `authRequired`, leaving the cleaned V78.25 application with no useful operating surface visible.

## Fix

Command now waits for the existing authentication lifecycle:
- `auth:restored`
- `auth:signed-in`
- `auth:organization-switched`

It does not issue the initial protected Command read while authentication is still unresolved.

If authentication is actually required, Command remains visible and presents a clear sign-in state instead of appearing blank.

If the local service returns 502/503/504, Command remains visible and presents a reconnecting state.

## Security

No protected restaurant data is shown before authentication succeeds. The fix changes startup coordination, not server authorization.

# BLUE CURRENT V49.5.0 — ROLLOUT ACTIVATION CONTROL

V49 begins Blue Current scale operations.

## V49.01–V49.05

The first V49 wave converts a V48 rollout plan into an explicit per-location activation review.

Blue Current now evaluates each planned restaurant against live operating conditions before a human approves it for activation.

### Live activation preflight
Each planned location is checked for:

1. inclusion in the signed human EXPAND scope
2. inclusion in the current rollout plan
3. current readiness at or above the rollout plan readiness floor
4. no High/Critical leadership-attention state
5. no urgent predictive intervention requiring immediate leadership action

The preflight is recalculated from current operating data.

### Human activation approval

Adds:

`POST /api/rollout-activation-control/locations/:locationId/approve`

Approval requires:
- authenticated admin permission
- explicit approver
- location inside authorized scope
- current rollout-plan membership

If all gates pass, the administrator can approve the location for activation.

If one or more gates are open, approval is blocked unless a documented executive override reason is supplied.

### Important state separation

Approval does not mean deployment.

Approved locations are written as:

- `status: APPROVED_FOR_ACTIVATION`
- `deploymentState: NOT_DEPLOYED`
- rollout location state: `APPROVED_FOR_ACTIVATION`

Blue Current records that leadership approved activation but does not perform technical deployment.

### Activation ledger

Each approval records:
- organization
- rollout plan
- location
- rollout wave
- approver
- authenticated actor
- timestamp
- complete preflight snapshot
- whether an override was used
- override reason
- approval note
- deployment state

The event is also audited and published to realtime listeners.

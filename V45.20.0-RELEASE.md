# BLUE CURRENT V45.20.0 — SHADOW EXECUTION BOUNDARY

## Release scope

V45.16–V45.20 introduces the separately certified execution-boundary architecture while deliberately keeping live restaurant mutation disabled.

### V45.16 — Strict Action Adapter Registry
Adds an explicit allowlist of command adapters for:
- kitchen fire pacing
- temporary seating buffers
- staffing contingency coverage
- guest manager-touch planning
- revenue recovery planning
- temporary runner support

Each adapter declares:
- domain
- allowed payload fields
- hard limits
- shadow handler
- compensation contract
- live handler

Every live handler is currently `null`.

### V45.17 — Execution Preflight
Before a command draft can enter shadow execution, Blue Current verifies:
- command draft status
- emergency-stop state
- adapter allowlisting
- payload limits
- shadow handler presence
- absence of live handlers
- compensation support

### V45.18 — Shadow Idempotency + Compensation Contracts
Shadow execution requires an idempotency key.

Reusing the same draft/idempotency-key pair returns the existing shadow result rather than reprocessing it.

Every allowlisted adapter declares a rollback/compensation contract even though shadow execution does not change live state.

### V45.19 — Emergency Stop + Canary Architecture
Emergency stop defaults to engaged.

This release only supports `engage-stop`; it deliberately does not expose a release action while live execution remains uncertified.

Canary controls exist structurally but are locked to:
- 0% live traffic
- `liveTraffic: false`

### V45.20 — Shadow Execution Boundary Readiness
Adds readiness certification across:
- strict adapter allowlisting
- absence of live handlers
- preflight
- idempotency
- compensation contracts
- emergency stop
- shadow execution
- zero-percent live canary
- command-draft separation
- live-state isolation

## Safety boundary
V45.20.0 still has no live execution implementation.

The adapter registry explicitly reports:
- `liveExecutionEnabled: false`
- all `liveHandler: null`
- emergency stop engaged
- canary live percentage 0

Shadow execution produces simulation records only:
- `status: shadow-simulated`
- `liveExecutionAllowed: false`
- `liveStateChanged: false`

## Operation V position
The next logical milestone is controlled execution certification itself: immutable execution policies, dual authorization for live release, per-domain production adapters, real compensation implementation, circuit breakers, observation windows, canary promotion criteria, and automatic rollback.

Live mutation should remain disabled until that separate milestone proves the boundary under production-like tests.

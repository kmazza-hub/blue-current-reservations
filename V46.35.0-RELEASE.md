# BLUE CURRENT V46.35.0 — REPOSITORY IMPACT CERTIFICATION

## Release scope

V46.31–V46.35 adds the repository-impact gate that must sit between a certified retirement candidate and any future code deletion.

This release still does not delete files.

### V46.31 — Read-Only Repository Impact Analyzer
Adds a server-side read-only analyzer that scans source files while excluding:
- node_modules
- .git
- database
- coverage
- dist/build output

For a surface ID it reports:
- exact repository references
- HTML section ownership
- deferred script ownership
- startup-registry dependencies
- API references
- test references
- inferred owned files

No write/delete operation is exposed.

### V46.32 — Dependency + Ownership Graph
Each analyzed surface receives a dependency graph containing:
- owned files
- inbound references
- startup dependencies
- API usage
- test coverage
- HTML ownership
- script ownership

Repository-impact blockers are created when startup/API/non-owned dependencies remain.

### V46.33 — Rollback Plan
Every repository-impact analysis produces a plan-only rollback specification:
- exact files to back up
- restore strategy
- post-change validation commands
- SHA-256 scope digest

Current state:
- `archiveGenerated: false`
- `codeDeletionAllowed: false`

### V46.34 — Human Deletion-Plan Authorization
A retirement candidate must have a prior `retirement-candidate-certified` record before a deletion plan can be created.

Human authorization:
- is blocked while repository-impact blockers remain
- records authorizer, timestamp, note, and scope
- authorizes the deletion plan only

Authorization scope:

`deletion-plan-only`

### V46.35 — Deletion-Plan Certification
The plan readiness gate checks:
- retirement certification
- repository impact
- zero startup dependencies
- zero API references
- zero inbound references
- direct test coverage
- rollback-plan digest
- human authorization
- absence of delete capability

A fully passing plan can reach:

`deletion-plan-certified`

Even then:
- `codeDeletionAllowed: false`
- `deletionExecuted: false`

There is no delete API endpoint in this release.

## Real repository finding
The analyzer was run against the existing `enterpriseValuePlanCenter`.

It correctly returned `impact-review-required` with:
- 3 owned files
- 7 inbound references
- 1 startup-registry dependency
- 1 API-reference set
- 2 direct test references

Blockers included startup registry, API review, and non-owned inbound references. This demonstrates the new gate prevents a superficially redundant surface from being authorized for deletion before dependency cleanup.

## New API
- `GET /api/operator-fine-comb/repository-impact?surfaceId=<id>`

This endpoint is authenticated and restricted to write/admin-capable users.

No DELETE route or repository mutation route is added.

## Fine-comb policy

`analyze → plan → authorize`

V46.35 stops there.

The next wave should perform **dependency-removal rehearsal** for a deletion-plan-certified surface:
- generate exact code-removal patches without applying them
- validate startup registry after simulated removal
- validate API/test impact
- build an actual rollback archive
- run the full validator against a disposable simulated-deletion copy
- produce a final deletion change set for explicit human approval

Permanent deletion should still not occur in the authoritative repository during that rehearsal.

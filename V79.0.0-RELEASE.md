# V79.0.0 — Live Data Source Truth & Integration Readiness

V79 establishes an explicit source-of-truth layer for pilot/live restaurant data.

## Why

Blue Current already has provider adapters and a canonical integration contract, but Command needs to know whether each operating domain is:
- local-only
- provider-backed
- fresh
- stale
- historical
- certified for live decision support

V79 makes that status explicit.

## Source domains

Blue Current now tracks source truth for:
- reservations
- service
- kitchen
- labor
- inventory
- sales
- guests

Each domain includes:
- provider(s)
- canonical event count
- latest received timestamp
- age in minutes
- freshness state
- safe-for-live-decision flag

## Provider readiness

Provider status includes:
- mapping count
- canonical event count
- last event
- freshness
- quarantine count
- live certification state

Command receives this source-truth object with its normal operating picture.

The visible Command status no longer blindly says `Service live`.
It reports:
- `Live sources`
- `Partial sources`
- `Local data`

## Policy

Provider data is not automatically authoritative.
Freshness is required for live claims.
Stale provider data cannot masquerade as live.
Live certification remains required.
Blue Current still makes no claim of a live Toast connection without evidence.

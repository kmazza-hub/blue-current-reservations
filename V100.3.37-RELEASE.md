# Blue Current V100.3.37 — Frontline Request Contract Integrity

This closing wave makes incomplete frontline requests clear and recoverable without changing successful operator workflows.

## Clear restaurant identity

- Shift creation, schedule publication, and week copying return HTTP 400 when restaurant identity is missing.
- Employee and shift-template creation return HTTP 400 when restaurant identity is missing.
- Clock-in, AI decisions, AI refresh, and reservation creation require explicit restaurant identity.
- Valid but unauthorized restaurants still return HTTP 403.

## Clear labor actions

- Clock-in, clock-out, break start, and break end require explicit employee identity.
- Schedule publishing and week copying require an explicit week start.
- Scheduling validation failures now carry HTTP 400 rather than becoming internal-server errors.
- Scheduling services can no longer silently choose the current week for a missing publish/copy request.

Successful Floor, Host, Service, Kitchen, Staff, Scheduling, and Time Clock behavior is unchanged. No database files are included.

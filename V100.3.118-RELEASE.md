# V100.3.118 — Connected Working Shift Demo

Open `/working-shift-demo.html` directly or use **Open Working Shift Demo** on
Command. The protected page reuses existing sign-in sessions and offers the
Frank Koch demo shortcut. Command, Guests, Service, Team, Kitchen, Inventory,
Performance, Execution, Executive and Integrations share one fictional dinner.

The starting scenario contains ten fictional parties, three occupied sample
tables, cooking/ready/served tickets, six demo team members, sample stock and
recipes, three completed sample sales, and manager-owned execution tasks. All
figures derive from those records. Sample Thanksgiving service, table inventory,
sections, staff, menu, capacity and policies are unapproved illustrations.

A host can save a fictional phone booking, mark arrival, optionally waitlist,
explicitly choose a fitting available table and working server, and seat. Seating
creates one cooking ticket. Kitchen ready/serve actions update floor truth and
deduct recipe stock. Completion requires served food, records a simulated sale,
and sends the table to cleaning. Cleaning returns it to availability. Team
attendance, sample stock receipt and execution task changes are persisted.
Active server coverage and insufficient inventory are protected. Repeated service
completion or serving cannot double-count sales or stock.

The Integrations view labels every external vendor connection **Not connected**.
Its connector round trip is a local saved simulation and sends no network calls,
SMS, reservations, payments or purchase orders to outside systems. No financial
attribution, actual margin, payroll, real operating readiness or rollout is
claimed. Executive explicitly retains real restaurant HOLD.

## Isolation and access

`/api/working-shift-demo` is authenticated and organization-scoped. It derives a
hashed per-organization filename beside the primary database; it does not share
the primary store or the existing holiday rehearsal. Host, kitchen and manager
actions retain separate permission checks. The existing serialized demo engine
provides stale-version rejection, atomic file replacement, explicit seating and
restart persistence. Reset requires manager authority and an exact confirmation;
it affects only that organization's fictional working shift, keeping version
numbers monotonic. Runtime demo JSON files are excluded recursively from Git and
Docker and rejected by the release-data guard.

## Meeting walkthrough

1. Sign in as Frank Koch, open Working Shift Demo, and review the populated shift.
2. In Service, choose Demo Quinn, explicitly choose an available table, and seat.
3. In Kitchen, mark that ticket ready, then served.
4. Check Inventory and Performance: serving uses recipe stock; sales remain tied
   to completed parties. In Service, complete the party and mark the table clean.
5. Start Demo Riley working in Team, receive fictional stock in Inventory, and
   complete a manager task in Execution. Executive reflects the same records.
6. In Integrations, explain the unconnected systems and run the local simulation.
7. Reset the fictional shift if another walkthrough needs the starting scenario.

Validation includes a 17-check new lifecycle suite and an isolated HTTP test for
roles, authentication, cross-organization separation, unchanged primary business
records, unchanged holiday rehearsal, live HOLD, stale writes, restart and
sign-out. `npm run certify:universal` also runs the existing full release suite.
Browser/hosted verification and actual GitHub/Render results must be reported
separately from local certification. No physical iPad/printer acceptance or
restaurant go-live approval is supplied by this release.

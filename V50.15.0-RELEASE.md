# BLUE CURRENT V50.15.0 — PRODUCTION INCIDENT COMMAND

V50.11–V50.15 adds one human-led incident command workflow across production support, observability, and SLO state.

## Incident intake

Production Incident Command reads existing V50.10 support events plus the existing telemetry/observability incident stream.

Open support and observability signals are surfaced together with:

- severity
- source
- location when known
- current owner
- linked incident reference
- current status

Blue Current does not automatically open an incident command from those signals.

Incident creation is human initiated.

## Human incident command

Adds:

POST `/api/production-incident-command`

Each incident command can capture:

- title
- severity
- incident commander
- affected restaurants
- affected domains
- business impact
- service impact
- linked production-support events
- linked observability incidents
- current SLO / error-budget state
- runbook / recovery procedure
- operator note

Affected restaurant scope is permission checked.

## Incident workflow

Adds:

POST `/api/production-incident-command/:incidentId`

Supported human actions:

- `acknowledge`
- `contain`
- `communicate`
- `recover`
- `resolve`

### Containment

Containment is recorded as:

`containmentStatus: HUMAN_RECORDED_CONTAINMENT`

Blue Current records that a human incident team performed containment. It does not execute containment.

### Communications

Communication checkpoints record:

- actor
- detail
- timestamp

### Recovery evidence

Recovery evidence records:

- actor
- recovery evidence
- timestamp

### Resolution

Resolution requires a human-recorded resolution note.

Blue Current does not resolve incidents autonomously.

## SLO and observability linkage

Each incident captures the current existing ReliabilityAutomationService state:

- SLO status
- breached objectives
- warning objectives
- remaining error budget

Existing observability incidents are linked read-only rather than duplicated.

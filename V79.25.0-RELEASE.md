# V79.25.0 — Provider Connection Readiness & Live Integration Gate

V79.25 converts raw provider connectivity into an explicit pilot-readiness decision.

## Provider readiness checks

Each provider is evaluated for:

- Blue Current location mapping
- canonical event flow
- event freshness within 30 minutes
- zero open quarantine items
- required domain coverage
- explicit live-provider certification

The required pilot domains are currently:

- reservations
- service
- kitchen
- sales

Labor, inventory, and guest-domain coverage remain valuable but are not required for the first readiness decision.

## Decisions

Each provider receives:

- `NOT_CONNECTED`
- `HOLD`
- `READY`

A provider adapter existing in the repository is not enough to be ready.

A provider can have mapping and live event flow and still remain `HOLD` until all readiness gates pass.

## Command

The existing Command source indicator now understands provider readiness.

It may show:

- `Local data`
- `Partial sources`
- `Live sources`
- `Pilot-ready source`

No new operator-facing engine or screen was added.

## API

`GET /api/integrations/provider-readiness`

## Safety / truthfulness

Blue Current still does not make a live Toast/Square/Clover claim merely because an adapter exists.

Provider data is not automatically authoritative, and explicit live certification remains required.

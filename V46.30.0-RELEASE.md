# BLUE CURRENT V46.30.0 — RETIREMENT CERTIFICATION

## Release scope

V46.26–V46.30 strengthens the fine-comb process so a hidden-preview surface cannot become a retirement candidate without multi-day evidence, owner sign-off, fresh manifest validation, and clean workflow results.

No code is permanently deleted.

### V46.26 — Multi-Day Preview Evidence
Adds persistent preview observations for surfaces hidden behind an approved deprecation feature flag.

Each observation records:
- surface ID
- timestamp
- manager workflow coverage
- task failures
- regressions
- operator note
- preview-hidden state

Retirement certification requires observations across at least 3 distinct days and at least 3 preview snapshots.

### V46.27 — Task Outcome + Time-to-Resolution Metrics
Operator evidence now supports:
- task-started events
- task-completed events
- success/failure outcomes
- duration measurement
- per-role completion metrics
- success rate
- average resolution time

Current retirement thresholds require:
- at least 95% task success
- no more than 15 minutes average resolution where duration evidence exists

### V46.28 — Manifest Expiry + Revalidation
Deprecation manifests now:
- expire after 72 hours
- require revalidation before hide preview can be enabled
- recheck manager workflow coverage
- recheck candidate eligibility
- record last revalidation time/status

An expired or invalid manifest cannot enable preview hiding.

### V46.29 — Owner Sign-Off
Each retirement candidate requires explicit owner sign-off.

The sign-off records:
- surface
- owner
- decision
- note
- timestamp

Missing or non-approved owner sign-off blocks retirement eligibility.

### V46.30 — Retirement Candidate Certification
Adds a separate retirement-certification gate.

A surface must pass:
- approved manifest
- valid/revalidated manifest
- active reversible hide preview
- 3 observed days
- 3 preview observations
- 100% workflow coverage throughout preview
- zero preview regressions/failures
- task-success threshold
- time-to-resolution threshold
- owner approval

Passing surfaces can become:

`retirement-candidate-certified`

This status still explicitly sets:
- `automaticDeletion: false`
- `codeDeletionAllowed: false`

A later regression causes the surface to fail retirement eligibility again.

## Fine-comb policy
`certify-retirement-never-auto-delete`

This release creates evidence-backed retirement candidates only. Permanent deletion remains a later explicit decision after human review and repository-impact analysis.

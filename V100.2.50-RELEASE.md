# V100.2.50 — Service Intake Handoff

This wave consumes the clean Host Stand seating event created in V100.2.49 and establishes the first authoritative Service-side intake state.

- A confirmed seating event is captured into a persistent active-service-party queue.
- Duplicate handoffs for the same guest/party/table key are collapsed.
- Service intake publishes `bc:service-party-received` for downstream Service UI/operations.
- `window.BlueCurrentServiceHandoff.getActive()` exposes current active parties.
- A narrow `clear()` seam is provided for a later check-close/table-turn lifecycle.
- Host, reservation, waitlist, Guests, Guest Intelligence, floor geometry, and V100.2.48 readability are not redesigned.

This wave deliberately establishes the lifecycle/data seam before changing the Service screen.

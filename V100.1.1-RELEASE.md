# V100.1.1 — Command Auth Transport Hotfix

## Purpose

Repair the P0 defect discovered during live V100.1 acceptance testing where Command authenticated successfully, then returned the operator to login after the next 30-second operating-picture refresh.

## Root cause

`hospitalityOsShell.js` refreshed `/api/command/operating-picture` with a raw `fetch()` call that did not use Blue Current's canonical authenticated Cloud API transport. The protected refresh could therefore reach the server without the active Bearer session and receive `401 Unauthorized`.

## Repair

- Route protected Command refreshes through `BlueCurrentCloudApi.request()`.
- Synchronize the active Blue Current Bearer token into the Command request transport.
- Preserve the existing 30-second Command refresh cadence.
- Preserve canonical session-expiry handling for genuine `401` responses.
- Keep the V100.0.0 commercial baseline version unchanged.
- Extend the V100.1 shell regression marker to V100.1.1.
- Add a dedicated regression gate that fails if Command returns to a raw unauthenticated fetch path.

## Acceptance path

1. Sign in from a clean/hard-refreshed browser.
2. Command loads.
3. Stay on Command for at least 45 seconds.
4. Confirm no redirect to login after the 30-second refresh.
5. Confirm Command/Guests/Service/Team/Kitchen navigation remains available.
6. Confirm Kitchen Pressure opens the intended operator workspace.

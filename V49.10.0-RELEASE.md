# BLUE CURRENT V49.10.0 — TECHNICAL ACTIVATION READINESS

V49.06–V49.10 adds the technical gate between rollout approval and production go-live.

## Technical readiness checks

Each rollout location is evaluated against:

1. Human activation approval exists.
2. Location operating configuration exists.
3. At least one authorized user can access the location.
4. Floor/table model exists.
5. Reservation data path is configured.
6. Kitchen operating model or connector is configured.
7. Workforce roster or labor connector is configured.
8. External production-capable connector state is surfaced as an advisory readiness signal.
9. V49 rollout activation preflight passed or was explicitly overridden.

Required checks produce launch blockers. External connector connectivity is currently advisory because Blue Current must not claim a production connector is connected when the runtime only contains sandbox/not-configured connector records.

## Technical activation packet

Adds:

`GET /api/technical-activation-readiness/locations/:locationId/packet`

The packet records:

- readiness percent
- required checks passed / total
- blockers
- advisory warnings
- complete check results
- go-live authorization state
- production cutover state
- safety policy

## Human go-live authorization

Adds:

`POST /api/technical-activation-readiness/locations/:locationId/authorize-go-live`

Authorization requires:

- authenticated admin permission
- location inside authorized scope
- explicit go-live approver
- current rollout-plan membership

If technical blockers remain, authorization is blocked unless a documented executive override reason is supplied.

The authorization records:

- organization/location/wave
- approver
- authenticated actor
- timestamp
- technical readiness snapshot
- blockers at authorization time
- override status and reason
- planned launch window
- rollback owner
- note

## Critical separation

Go-live authorization does not perform production cutover.

Every authorization is stored as:

- `status: AUTHORIZED_FOR_GO_LIVE`
- `productionCutoverState: NOT_PERFORMED`

Policy:

- `technicalReadinessDoesNotCutOver: true`
- `humanGoLiveAuthorizationRequired: true`
- `adminAuthorizationRequired: true`
- `blockerOverrideRequiresReason: true`
- `authorizationDoesNotDeploy: true`
- `automaticProvisioning: false`
- `automaticCutover: false`
- `automaticGoLive: false`

## Focused lifecycle validation

The focused test verifies:

- a fully configured location reaches 100% required technical readiness
- missing location configuration/data produces launch blockers
- go-live authorization succeeds for a ready location
- authorization remains `NOT_PERFORMED` for production cutover
- a blocked location cannot be authorized without an override
- documented executive override is persisted
- technical packet is generated
- audit and realtime events are emitted

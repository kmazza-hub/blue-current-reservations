# BLUE CURRENT V51.55.0 — PILOT LAUNCH CONTROL

V51.51–V51.55 adds the final human-controlled launch gate between a certified pilot deployment package and an actual restaurant pilot.

## Launch-control gates

Each pilot location is evaluated against 10 launch gates:

1. PILOT_LOCATION_SELECTED
2. DEPLOYMENT_PACKAGE_CERTIFIED
3. CONFIGURATION_FROZEN
4. CONFIGURATION_UNCHANGED
5. LAUNCH_WINDOW
6. LAUNCH_OWNER
7. OPERATOR_ROSTER
8. SUPPORT_BRIDGE
9. NO_OPEN_BLOCKERS
10. PRELAUNCH_EVIDENCE

## Configuration freeze

When launch control is configured, Blue Current snapshots the pilot restaurant configuration and stores a SHA-256 fingerprint across:

- location identity/status
- tables
- sections
- scoped memberships
- connector configuration/status

Before authorization, the current configuration is compared against the frozen hash.

If configuration changes after the freeze, the launch gate reopens.

## Pilot launch ownership

Launch control requires:

- launch owner
- launch window start
- launch window end
- confirmed pilot operator roster
- live support bridge/channel
- support owner
- escalation owner
- human pre-launch evidence

## Launch blockers

Human launch blockers can be recorded during configuration.

Any unresolved blocker prevents launch authorization.

Resolving a blocker requires human resolution evidence.

## Human authorization

Final state:

`PILOT_LAUNCH_AUTHORIZED`

Authorization requires:

- all 10 launch gates passing
- admin permission
- human authorization evidence
- human authorization note

Authorization is deliberately separate from execution.

It does not:

- start the runtime
- execute a deployment
- perform go-live
- modify restaurant operating state

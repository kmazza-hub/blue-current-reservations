# BLUE CURRENT V50.10.0 — PRODUCTION HEALTH & SUPPORT COMMAND

V50.06–V50.10 adds the steady-state production support command layer after V50.5 Production Operations Handoff.

## Design principle

This wave reuses Blue Current's existing reliability/SLO and telemetry infrastructure.

It does NOT create a second observability stack.

The production support command combines:

- accepted production-location ownership
- platform SLO / reliability state
- telemetry / observability incidents
- restaurant readiness
- operating attention
- urgent predictive pressure
- maintenance-window context
- human-created support events
- acknowledgment / escalation / resolution timeline

## Accepted production registry

Only locations already accepted through V50.5 appear in Production Health & Support Command.

Each location retains:

- production support owner
- escalation owner
- support coverage
- maintenance window
- current readiness
- current operating attention
- current predictive pressure

## Production health rollup

Each accepted restaurant is evaluated against:

1. platform SLO state is not breached
2. no open critical platform incident
3. restaurant readiness is at least 70
4. operating attention is not High/Critical
5. no urgent predictive intervention
6. no open critical production support event

Health states:

- `healthy`
- `degraded`
- `critical`

Portfolio command states:

- `production-support-healthy`
- `production-support-degraded`
- `production-support-critical`

## Existing observability reuse

Production Health & Support Command reads the existing telemetry system for:

- p95 latency
- server errors
- open observability incidents
- critical observability incidents

It reads the existing ReliabilityAutomationService for:

- SLO status
- reliability score
- breached objectives
- warning objectives
- remaining error budget

## Human support event workflow

Adds:

`POST /api/production-health-support/locations/:locationId/events`

A support event captures:

- location
- severity
- title / description
- current support owner
- current escalation owner
- optional linked observability incident ID
- creator / timestamp
- event timeline

Supported severity:

- info
- warning
- critical

Support events can then be updated through:

`POST /api/production-health-support/events/:eventId`

Supported human actions:

- `acknowledge`
- `escalate`
- `resolve`

Every action records actor, time, note, and audit/realtime evidence.

## Maintenance awareness

The accepted location's maintenance-window definition is surfaced directly in production support context.

The first implementation treats explicitly marked `active` / `now` windows as active rather than guessing whether a free-form maintenance description is currently in effect.

## Safety policy

- `supportActionsHumanInitiated: true`
- `escalationHumanInitiated: true`
- `incidentLinkageReadOnly: true`
- `automaticAcknowledgement: false`
- `automaticEscalation: false`
- `automaticRemediation: false`
- `autonomousProductionChanges: false`

Blue Current may identify degradation and provide the operating picture.

It does not acknowledge incidents, escalate people, remediate systems, or change production automatically.

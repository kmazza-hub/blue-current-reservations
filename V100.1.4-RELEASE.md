# V100.1.4 — Command Auth State Synchronization Hotfix

## Purpose
Fix the remaining stale Command access banner after successful authentication, where `/api/auth/me` and bootstrap return 200 but Command still renders `Sign in` / `Sign in required`.

## Changes
- Allows Command to recognize authenticated UI state when both a hydrated `authenticatedUser` and current bearer token are present, while leaving protected Command requests server-authoritative.
- Adds an `authenticatedUser` state-hydration listener that clears the stale auth-required presentation and forces an immediate Command refresh.
- Preserves coordinator authority when live authentication evidence is absent.
- Advances the operator shell marker to `100.1.4`.
- Updates prior V100.1.x regression tests to accept the current shell marker and adds a dedicated V100.1.4 regression test.

## Safety
- No database data changes.
- No persistence changes.
- No RBAC changes.
- No commercial baseline version change (`100.0.0`).
- A stale/invalid bearer token still fails on the protected server request and returns Command to auth-required state.

# Blue Current V100.1.2 — Command Lifecycle & API Contract Hotfix

## Scope

P0 stabilization of the authenticated Command lifecycle discovered during the V100 Operational Audit.

## Repairs

- Registers Command authentication lifecycle listeners before evaluating initial auth state, eliminating the stale-appState early-return race.
- Treats `BlueCurrentAuthSession` as authoritative when installed; stale `appState.authenticatedUser` can no longer resurrect an invalid prior session.
- Fresh successful sign-in immediately clears the access banner and triggers the initial Command operating-picture refresh.
- Preserves the 30-second authenticated refresh cycle.
- Normalizes all `commandFetch()` consumers to the parsed-payload contract returned by `BlueCurrentCloudApi.request()`; removes stale raw `Response.json()`, `.ok`, and `.status` assumptions.
- Establishes protected-route organization/location scope immediately after authentication in the API router.
- Replaces invalid `auth.allowedLocationIds` consumption with the authenticated membership location scope.
- Removes heavyweight pilot-readiness/certification recomputation from the 30-second Command hot path. Dedicated pilot endpoints remain unchanged.

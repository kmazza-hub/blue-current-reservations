# BLUE CURRENT V47.30.0 — MANAGER OPERATING RHYTHM

## Scope

V47.26–V47.30 unifies the V47 operating layers into one continuous manager workflow.

The goal is to make Blue Current useful across the entire shift, not only as a collection of individual dashboards.

The operating rhythm is:

Pre-shift priorities
→ committed shift plan
→ predictive warnings
→ live owned actions
→ profitability control
→ shift handoff
→ post-shift closeout

## V47.26 — Unified Shift Snapshot

Adds `ManagerOperatingRhythmService`.

It composes current information from:

- Restaurant Command Center
- Hospitality Performance Command
- Action Workspace
- Outcome Measurement
- Service Profitability Intelligence
- Predictive Shift Control
- existing shift handoffs

The snapshot builds one current management narrative instead of forcing the manager to reconstruct the shift state manually.

## V47.27 — Pre-Shift Plan

Adds:

`POST /api/manager-operating-rhythm/plan`

The manager commits the current highest-value priorities before service.

The plan captures:

- shift
- manager
- operating intent
- selected current priorities
- readiness score at plan time
- profitability state at plan time
- predictive interventions visible at plan time
- creation timestamp

If explicit priorities are not supplied, Blue Current proposes the current top three Hospitality Performance opportunities.

The manager still creates the plan.

## V47.28 — Live Shift Rhythm

The operating-rhythm snapshot continuously connects:

- committed priorities
- active owned actions
- completed actions
- predictive interventions
- current controllable contribution
- modeled controllable margin
- realized action impact
- current highest profit constraint

A five-stage rhythm score tracks whether the complete management cycle is being executed:

1. Pre-shift
2. Live service
3. Profit control
4. Handoff
5. Post-shift

## V47.29 — Manager Handoff

Adds:

`POST /api/manager-operating-rhythm/handoff`

Blue Current can draft the handoff from the current shift state.

It carries forward:

- completed action outcomes
- top remaining profit constraint
- unresolved active actions
- near-term predictive interventions
- operating narrative

The manager can supply or override the handoff summary.

The result is stored in the existing `shiftHandoffs` collection so it remains compatible with the Restaurant Command Center handoff model.

## V47.30 — Post-Shift Closeout

Adds:

`POST /api/manager-operating-rhythm/closeout`

The closeout captures:

- priority count
- completed actions
- carryover actions
- realized impact
- realization rate
- ending controllable contribution
- ending controllable margin
- remaining top constraint
- manager closeout note

Closeout states:

- `closed-clean`
- `closed-with-carryover`
- `carryover-required`

This creates a durable shift result rather than ending the operating story when service stops.

## Manager Operating Rhythm UI

Adds a new **Manager Operating Rhythm** section after Predictive Shift Control.

It shows:

- rhythm completion score
- readiness
- current priority count
- active actions
- controllable contribution
- realized impact
- latest handoff
- latest closeout
- five-stage rhythm status
- current prioritized opportunities
- continuous operating narrative

Manager controls:

- Commit Shift Plan
- Post Handoff
- Close Shift

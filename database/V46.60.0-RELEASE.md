# BLUE CURRENT V46.60.0 — NEXT RETIREMENT CANDIDATE SELECTION

## Release scope

V46.56–V46.60 begins the next fine-comb cycle without deleting another module.

The system now ranks the current retirement-candidate pool and requires an explicit human selection before any preview/certification pipeline can start.

### V46.56 — Candidate Pool

Blue Current builds the pool from the existing Operator Surface Rationalization classification.

Only `deprecation-candidate` surfaces are considered.

The pool excludes:
- already retired surfaces
- primary/merge/diagnostics surfaces by classification
- surfaces protected by current Manager, Executive, or Technical default navigation from automatic shortlist selection

The current repository contains 43 deprecation-candidate surfaces under the existing classification rules.

### V46.57 — Batch Repository Impact

Adds:

`POST /api/operator-fine-comb/candidate-impact`

The read-only endpoint evaluates candidate IDs in batches and returns:
- owned-file count
- startup dependencies
- API references
- direct test references
- operational inbound references
- total repository references
- rollback file count
- current impact blockers

The endpoint requires retirement assurance to be open.

### V46.58 — Evidence-Based Ranking

Each candidate receives a score using:
- 35% operator-use independence
- 30% workflow independence
- 25% repository-removal ease
- 10% cluster redundancy

Operator-use evidence comes from the existing consolidation evidence stream.

Workflow protection is derived from the current Manager/Executive/Technical default navigation.

Repository ease comes from the real Repository Impact analyzer.

Cluster redundancy is a naming-cluster signal intended only as a tie-breaker / consolidation indicator.

### V46.59 — Top-Three Shortlist

The engine sorts the full candidate pool and exposes the highest-scoring three candidates that are not protected by role-default navigation.

Protected workflow surfaces can still be viewed in the complete ranking but cannot be selected through this gate.

The ranking is advisory and does not hide or modify a candidate.

### V46.60 — Explicit Human Selection Gate

A candidate must be explicitly selected from the current top-three shortlist.

A selection records:
- surface ID
- rank
- score
- human rationale
- selection timestamp
- retirement-assurance digest

Selection status:

`selected-for-preview-pipeline-only`

The selection explicitly records:
- `previewStarted: false`
- `codeDeletionAllowed: false`
- `deletionExecuted: false`

Selecting a protected workflow surface is blocked.

# V73.0.0 — End-to-End Restaurant Workflow Certification & Pilot Readiness

V73 certifies the operating lifecycle rather than isolated backend modules.

## Reservation lifecycle hardening
Reservation status changes now enforce a lifecycle:
- pending/booked -> confirmed/cancelled
- confirmed -> arrived/cancelled/no-show
- arrived -> seated/cancelled/no-show
- seated -> completed/cancelled
- terminal states cannot jump back into active service

Reservation updates are tenant-scoped and event creation occurs inside the same transaction.

## Atomic seating
Seating now validates:
- reservation organization
- table organization
- location match
- reservation status
- table availability
- table capacity

Reservation, table, and reservation event are committed together.

## Service completion
New:
`POST /api/reservation-operations/complete`

Completion atomically:
- marks the reservation completed
- records completion time
- releases the assigned table
- clears guest/covers/seating timestamps from the table
- records a reservation completion event

## Workflow certification
New:
`GET /api/system/workflow-certification`

It validates live operational relationships across:
- reservations
- active tables
- staff assignments
- kitchen tickets
- inventory
- V72.50 operational integrity

It reports `pilotWorkflowReady` but performs no automatic repair.

## End-to-end certification scenario
V73 test coverage executes:
reservation creation -> arrival -> section/server assignment -> seating ->
kitchen received/cooking/ready/served -> purchase-order action ->
executive sourced snapshot -> service completion -> table release ->
final cross-module certification.

The scenario also verifies cross-tenant mutation rejection, audit events, and realtime events.

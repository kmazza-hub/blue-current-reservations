# V100.2.2 — Guest Search Consistency & Readability

## Operational audit finding
The Host Stand could successfully add a walk-in to the visible waitlist, but Find Guest searched a separate static array. A guest could therefore be visibly waiting while search incorrectly reported "No matching guest found." The search field also had insufficient foreground contrast in the dark Host Stand presentation.

## Repair
- Guest search now derives its operating dataset from the currently rendered waitlist, arrivals, and reservation list, with existing profile/demo context as a fallback.
- Live operating state wins when the same guest exists in more than one source.
- Newly added local walk-ins and reservations become searchable immediately without maintaining a second mutable guest store.
- Search-field text, caret, placeholder, focus border, and empty-result copy now have explicit dark-environment contrast.

## Boundaries
This repair makes the current Host Stand UI internally consistent. It does not claim new durable server persistence for the legacy/demo Host Stand mutation path; durable persistence remains a separate operational-audit item.

## Acceptance
Add walk-in → visible on waitlist → Find Guest → same guest found.

# V100.1.3 — Authentication Overlay Interaction & Focus Hotfix

## Purpose

Repair the live P0 authentication overlay defect proven during V100 Operational Audit acceptance testing.

Observed failure:

- the authentication overlay was visibly open;
- the login form existed and was valid;
- the submit listener was attached;
- the Sign in button was enabled and belonged to the correct form;
- but the open overlay still carried the HTML `inert` attribute;
- therefore browser interaction was blocked before form submission and no login network request fired.

## Changes

- Command's sign-in fallback now delegates to `BlueCurrentAuthOverlay.open()` when the authoritative overlay controller is available.
- Fallback opening explicitly removes both `inert` and `aria-hidden` from the visible authentication overlay.
- Focus is cleared from Command before Command becomes inaccessible during authentication.
- The active authentication overlay makes the Command shell inert and hidden from accessibility APIs.
- The login email field receives focus after the overlay becomes interactive.
- Before the authentication overlay closes, focus is cleared from the overlay.
- Successful authentication restores Command interaction and accessibility state.
- Regression coverage updated so V100.1.0–V100.1.2 checks remain compatible with the V100.1.3 shell marker.

## Preserved

- V100 commercial package version remains `100.0.0`.
- V100.1.0 operator-shell routing repair remains intact.
- V100.1.1 authenticated Command transport remains intact.
- V100.1.2 Command lifecycle/API contract repair remains intact.
- No database or persistence mutation is included.

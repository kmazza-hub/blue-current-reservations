# BLUE CURRENT V47.25.0 — PREDICTIVE SHIFT CONTROL

## Scope

V47.21–V47.25 moves Blue Current from current-state intelligence to preemptive operating control.

The new server-grounded forecast answers:

`What service constraint is likely to hit next, when will it hit, and what should the manager do before it happens?`

This is deliberately separate from the older client-only Predictive Operations panel. V47.25 uses current server-side operating data rather than reading rendered DOM values.

## V47.21 — Operating Signal Model

Predictive Shift Control combines:

- active reservation covers
- unassigned reservation covers
- waitlist covers
- long-wait exposure
- seated / available / unavailable seat capacity
- active kitchen tickets
- delayed kitchen tickets
- active kitchen item load
- ready / plating tickets
- unavailable kitchen stations
- workforce role coverage
- staffing gaps
- labor position
- callout risk
- revenue trend
- modeled profitability leakage

## V47.22 — 90-Minute Pressure Curve

The server produces forecast checkpoints for:

- now
- +15 minutes
- +30 minutes
- +45 minutes
- +60 minutes
- +90 minutes

Each checkpoint contains transparent pressure scores for:

- host / table capacity
- kitchen throughput
- labor capacity
- revenue pace
- combined operating pressure

Thresholds:

- Watch: 60
- Action: 75
- Critical: 88

The forecast uses a transparent operating-pressure heuristic.

It is explicitly marked:

`machineLearning: false`

## V47.23 — Time-to-Constraint

Blue Current detects the first operating dimension forecast to cross the action threshold.

The result contains:

- first constraint
- time to constraint
- projected pressure at crossing
- peak combined pressure
- model confidence

This lets the manager see the problem while there is still time to intervene.

## V47.24 — Preemptive Intervention Queue

When a dimension is forecast to cross threshold, Blue Current creates a manager intervention.

Current intervention families:

### Host / Table Capacity
Pre-assign parties, clear cleaning tables, and verify blocked inventory before the arrival wave.

### Kitchen Throughput
Rebalance the constrained station, prepare expo support, and protect the oldest ticket before the next seating wave.

### Labor Capacity
Move coverage before the demand peak while avoiding unnecessary labor additions.

### Revenue Pace
Protect conversion and capacity first, then use remaining inventory for the highest-value incremental demand.

Every intervention includes:

- ETA
- pressure
- severity
- operating evidence
- preemptive action
- owner
- expected impact
- human approval requirement

## V47.25 — Human-Controlled Predictive Decisions

Adds:

`POST /api/predictive-shift-control/interventions/:id/decision`

Supported decisions:

- accepted
- snoozed
- dismissed
- completed

Predictive decisions persist:
- organization
- location
- intervention
- decision
- owner
- note
- ETA
- pressure
- actor
- timestamp

They are also written to the audit trail and realtime event stream.

Policy:

- `humanApprovalRequired: true`
- `automaticExecution: false`

## API

### GET

`/api/predictive-shift-control?locationId=<location>`

Returns the full 90-minute forecast and active intervention queue.

### POST

`/api/predictive-shift-control/interventions/:id/decision`

Records a human manager decision.

## Model boundary

This is a transparent decision-support forecast, not a guaranteed prediction.

The model does not claim to be machine learning and does not hide its operating inputs.

The primary purpose is to create useful lead time for managers before a constraint becomes a live-service failure.

# BLUE CURRENT V50.20.0 — PRODUCTION RECOVERY & POST-INCIDENT REVIEW

V50.16–V50.20 adds the recovery-verification and lessons-learned layer after a human-resolved production incident.

## Recovery verification

Resolved incidents are evaluated against current production state.

For each affected restaurant Blue Current checks:

1. Production support health is not critical.
2. Restaurant readiness is at least 70.
3. No open critical production support event remains.

If no location-specific scope exists, platform reliability is used as the recovery signal.

The review also summarizes:

- incident start / resolution time
- incident duration in minutes
- business impact
- service impact
- incident commander
- human resolution
- recovery evidence
- current platform SLO/reliability state

## Human-authored post-incident review

Adds:

POST `/api/production-recovery-review/incidents/:incidentId/review`

A review requires:

- human-authored root cause
- at least one corrective action
- corrective-action owner
- repeat-risk assessment
- executive post-incident summary

Optional contributing factors are captured explicitly.

Repeat risk:

- low
- medium
- high
- critical

## Corrective actions

Each corrective action records:

- action
- owner
- due date
- status: `OPEN`
- execution state: `NOT_EXECUTED_BY_BLUE_CURRENT`

Blue Current records corrective work but does not execute it.

Each review also explicitly records:

- `correctiveActionsExecutedBySystem: false`
- `runtimeMutationPerformed: false`

## Human lessons acceptance

Adds:

POST `/api/production-recovery-review/reviews/:reviewId/accept-lessons`

Acceptance is admin-only and requires:

- named approver
- human closure / lessons note

Accepted state:

`POST_INCIDENT_REVIEW_ACCEPTED`

## Executive review record

The stored post-incident review provides the decision-ready executive record:

- duration
- impact
- recovery status
- root cause
- contributing factors
- corrective actions / owners / due dates
- repeat risk
- executive summary
- lessons acceptance
- closure note

## Safety policy

- `recoveryVerificationReadOnly: true`
- `rootCauseHumanAuthored: true`
- `correctiveActionsHumanOwned: true`
- `lessonsAcceptanceHumanRequired: true`
- `automaticCorrectiveActionExecution: false`
- `automaticClosure: false`
- `autonomousProductionChanges: false`

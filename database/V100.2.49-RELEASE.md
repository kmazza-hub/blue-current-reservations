# V100.2.49 — Seated Guest Handoff

This wave resumes the Host Stand lifecycle after the floor restoration/readability work.

- A party that is confirmed seated no longer remains as a stale card in the active waitlist.
- The guest is still persisted to the existing deduplicated Guests registry.
- Waitlist and seated counters continue to move exactly once.
- Seating publishes `bc:host-guest-seated` with guest, party size, context, and source so the downstream Service workspace has a clean handoff seam.
- Reservation → waitlist behavior and Guest Recognition remain intact.
- V100.2.47 floor geometry and V100.2.48 floor readability are untouched.

This is intentionally a narrow lifecycle wave: finish the host's responsibility cleanly before adding deeper Service behavior.

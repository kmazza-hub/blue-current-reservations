# V100.1.6 — Command Connectivity State Reconciliation Hotfix

## Problem
The authenticated Blue Current shell could remain stuck in a false `reconnecting` / `temporarily disconnected` state even while `/api/health`, `/api/auth/me`, `/api/bootstrap`, and the event stream were all returning HTTP 200 with valid organization/location data.

## Repair
- Keeps the V100.1.5 authoritative auth presentation behavior.
- Reconciles Command connectivity when authenticated bootstrap/cloud events complete.
- Clears stale Command transport backoff after verified authenticated connectivity.
- Forces an immediate Command refresh after successful connectivity reconciliation.
- Routes the live Command hot path through `BlueCurrentCloudApi.transportRequest`, preserving bearer/session enforcement while avoiding stale request-pipeline circuit/backoff state from unrelated startup traffic.
- Leaves genuine auth failures and genuine network/5xx failures authoritative.

## Scope
No database, persistence, RBAC, or server-authentication changes. Commercial package version remains `100.0.0`.

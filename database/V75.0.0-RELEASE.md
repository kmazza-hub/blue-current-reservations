# V75.0.0 — Universal Hospitality Integration Contract & Provider Adapter Framework

V75 creates the provider-agnostic integration boundary for Blue Current.

## Canonical contract

Blue Current now defines normalized hospitality events for:
- orders
- payments
- menu items
- inventory levels
- employees
- labor shifts
- reservations
- guests
- kitchen tickets

Provider-specific identifiers and payload shapes are translated into this contract before they can enter the Blue Current integration event stream.

## Provider adapter framework

Contract-ready normalization adapters are included for:
- Toast
- Square
- Clover

These adapters are mapping/normalization profiles. V75 does not claim live API connectivity, production credentials, partner approval, or provider certification.

## Identity mapping

External provider location IDs must be explicitly mapped to an authorized Blue Current location before ingestion.

This prevents a provider's restaurant/location identifier from being treated as a trusted Blue Current tenant/location identity.

## Delivery safety

Canonical ingestion provides:
- provider provenance
- deterministic duplicate suppression
- provider-event fingerprinting
- invalid/unmapped event quarantine
- provider health counters
- replay-safe event storage

Provider data is not automatically made authoritative operational state.

## Endpoints

- `GET /api/system/integration-contract`
- `GET /api/system/integration-health`
- `GET /api/system/integration-mappings`
- `POST /api/system/integration-mappings`
- `POST /api/system/integration-preview`
- `POST /api/system/integration-ingest`

## Safety boundary

V75 explicitly reports that Toast, Square, and Clover are **contract-ready**, not live-certified.

A real provider connection still requires provider credentials, granted API scopes, field-level certification, sandbox/live tests, webhook or polling verification, reconciliation, and human approval before production use.

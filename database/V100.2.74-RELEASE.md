# V100.2.74 — Scheduling Publication Integrity

Protects the truth boundary between Scheduling and live Staffing coverage.

A week is now exposed as **Published** only while its current shifts remain in published state and have not changed after the latest publication timestamp. Creating or editing a shift therefore returns the week to Draft until it is republished. Deleting a published shift explicitly invalidates that week's publication record.

This closes a real lifecycle gap: downstream Staffing coverage can no longer treat a modified schedule as certified merely because an older publication record still exists.

The wave changes no operator layout, adds no AI, adds no interval or MutationObserver, and preserves the existing Scheduling API contract (`publication` remains either the current publication object or `null`).

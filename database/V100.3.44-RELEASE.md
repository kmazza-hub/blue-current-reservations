# Blue Current V100.3.44

## Physical Operator Acceptance Evidence Gate

V100.3.44 prevents simulation scores or generic notes from being mistaken for real pilot acceptance.

- Every observation must identify a physical iPad, device model, iPadOS version, network, named operator, restaurant location, capture time, outcome, and workflow step.
- The observed location must match the current certified workflow binding.
- The complete launch → reservation → arrival → waitlist → seating → Floor → Service → Kitchen → Staff → interruption/recovery loop is required.
- LAN evidence is retained for early device testing but cannot produce final acceptance.
- Every workflow step requires hosted-pilot evidence before the gate becomes ready.
- Blocked outcomes, incomplete dimensions, low scores, mismatched location, or stale simulation/binding evidence fail closed.
- Final acceptance requires explicit human confirmation of both the physical device and hosted environment.

This release records no invented restaurant or device data, does not self-approve, and contains no database payload.

# BLUE CURRENT V46.65.0 — SELECTED CANDIDATE PREVIEW & EVIDENCE

## Release scope

V46.61–V46.65 takes only the explicitly selected top-three candidate into a reversible preview/evidence phase.

No permanent retirement occurs in this wave.

### V46.61 — Selection-Bound Preview

The preview engine requires an existing selection with:

`selected-for-preview-pipeline-only`

The preview is bound to:
- selection ID
- surface ID
- selection rank
- selection score
- baseline workflow coverage
- baseline operator-use evidence
- baseline task-quality evidence

A preview cannot start without explicit selection.

### V46.62 — Reversible Candidate Hide

Starting the preview hides only the selected surface.

The operation is reversible immediately through Restore Candidate.

State records:
- `reversible: true`
- `codeDeletionAllowed: false`
- `deletionExecuted: false`

No source file is removed.

### V46.63 — Preview Evidence Window

Each observation records:
- timestamp
- manager workflow coverage
- task failures
- regression signals
- task success rate
- average resolution time
- selected-surface operator-use count
- operator note

The readiness gate requires:
- at least 3 observations
- at least 3 distinct observed days
- 100% manager workflow coverage
- zero preview regressions / task failures
- at least 95% task success
- no increase in selected-surface operator-use evidence

### V46.64 — Owner Sign-Off + Repository Impact Refresh

The selected candidate requires explicit owner approval.

The preview can refresh the existing candidate-impact endpoint to capture:
- owned files
- startup dependencies
- API references
- operational inbound references
- test references

This is evidence refresh only; no repository mutation occurs.

### V46.65 — Certification Handoff Gate

When all preview checks pass, the state becomes:

`preview-evidence-complete`

This means the candidate is eligible to move into the existing certification pipeline.

It does NOT:
- certify automatically
- authorize deletion
- delete code
- start a repository rehearsal automatically

## Regression protection

A focused harness passed the full evidence gate with:
- 3 observations
- 3 distinct days
- 100% workflow coverage
- 100% task success
- owner approval
- refreshed repository impact

Then an injected regression immediately changed the candidate back to ineligible.

Restore Candidate successfully returned the preview to:

`preview-restored`

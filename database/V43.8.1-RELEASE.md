# Blue Current V43.8.1 — I/O Reliability Hotfix

This hotfix addresses Windows `EMFILE: too many open files` failures observed when the Executive pack initializes many protected API modules concurrently.

## Changes
- Process-local database snapshot after the first successful disk read.
- Concurrent initial reads are coalesced into one physical file read.
- Every caller receives an isolated clone so readers cannot mutate the shared snapshot.
- Serialized mutations operate from the in-memory snapshot and publish the new snapshot only after persistence succeeds.
- `EMFILE` and `ENFILE` are treated as transient I/O failures with bounded retry/backoff.
- Orphan temp-file cleanup is sequential rather than unbounded `Promise.all` file operations.
- Temporary-file opens are retried and file handles are always closed in `finally`.
- Database diagnostics expose disk reads, coalesced reads, cache reads, writes, retries, and the last I/O error.

No executive decision behavior or restaurant automation policy is changed by this hotfix.

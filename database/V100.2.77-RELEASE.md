# V100.2.77 — Time Clock Record Integrity

## Objective
Protect recorded Time Clock truth when managers correct punches.

## Changes
- Reject invalid clock-in and clock-out timestamps.
- Reject clock-out earlier than clock-in.
- A corrected clock-out cannot leave a timecard `active`.
- Removing a clock-out from a `completed` record produces `needs_review` rather than falsely implying the employee is actively working.
- A corrected clock-out safely closes an active break at the recorded clock-out time.
- Reject a corrected clock-out that predates an active break start.
- Preserve explicit `needs_review` state when a valid clock-out exists.
- Preserve organization isolation and existing Staffing/Scheduling contracts.

## Scope
No UI redesign. No new polling, timers, observers, AI, payroll, or HR features.

## Validation
Dedicated V100.2.77 lifecycle gate plus protected V100.2.70–V100.2.76 regression gates.

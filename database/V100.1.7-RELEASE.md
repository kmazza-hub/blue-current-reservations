# V100.1.7 — Command Shell Visibility Ownership Hotfix

## Root cause
The V100 Hospitality OS shell (`#blueCurrentCommand`) is inserted before the legacy `#command-center`. Two pre-V100 experience classifiers were still scanning top-level sections after startup:

1. `product-experience-v59.50.js` classified every section before `#command-center` as `.bc-advanced-surface`.
2. `.bc-advanced-surface` is intentionally `display:none !important` unless legacy advanced mode is opened.
3. If exempted only from that classifier, `operator-experience-v60.0.js` would classify the shell as a `.bc-deep-tool`, which is also `display:none !important` by default.

This explains the observed lifecycle exactly: the V100 shell renders first, then disappears after deferred legacy experience scripts run, while `hidden=false`, `visibility=visible`, and `opacity=1` remain true.

## Repair
- Exempt `#blueCurrentCommand` / `.bc-os-shell` from the legacy advanced-surface classifier.
- Register `blueCurrentCommand` as a CORE operator surface so it cannot be demoted to a deep tool.
- No authentication, API, database, RBAC, bootstrap, or server changes.

# V100.2.70 — Startup / Runtime Performance Hardening

Root cause addressed: focused startup still bypassed its own performance architecture in two places.

- 44 nonessential V37.11–V37.30 runtime diagnostics/release scripts no longer load during ordinary focused startup; they remain available through the existing deferred/full startup path.
- 8 recent Kitchen, Staffing, and Manager enhancement scripts no longer initialize while their workspaces are unused.
- A small on-demand runtime loader activates each domain in dependency order when the operator navigates to or approaches that workspace.
- `?full=1` remains available for intentional full-platform startup.
- No Host/Floor, Service lifecycle, Kitchen, Staffing, Manager, Cloud API, or existing startup-loader file is rewritten.

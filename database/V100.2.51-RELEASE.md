# V100.2.51 — Service Active Tables

This wave makes the V100.2.50 Host Stand → Service handoff visible to the operator without changing the stabilized Host Stand floor.

- The existing **Service · Run floor** quick action now opens a focused **Active tables** Service workspace.
- Active service parties are read from the authoritative V100.2.50 handoff queue.
- The Service workspace shows active tables, active covers, longest-seated time, guest/party context, table assignment when available, and elapsed seated time.
- New seating handoffs refresh the Service view live while it is open.
- **Complete service** clears the party from the active-service queue through the existing handoff API.
- Empty-state behavior is explicit: Service shows that there are no active handoffs rather than inventing data.
- Host Stand floor geometry, table readability, Reservations, Waitlist, Guests, and Guest Recognition/Memory are not redesigned.

This is intentionally the first visible Service surface. It keeps one job on one screen: **who has been seated and now belongs to Service?**

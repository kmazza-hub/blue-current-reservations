# V78.25.0 — Product Surface Consolidation & Legacy Version Retirement

This wave performs a product-wide cleanup without deleting backend capability.

## What changed

- Removed historical Vxx.x build labels from the normal restaurant-facing UI.
- Retired 377 development-era certification, release, rollout, expansion, and legacy engine surfaces from the normal application.
- Preserved those surfaces and their backend modules for engineering inspection.
- Added explicit developer inspection mode: `?advanced=1`.
- Rebuilt workspace routing around product concepts instead of development waves.
- Removed the public marketing footer/brand-close panel from the authenticated Hospitality OS experience.
- Current product version remains available through diagnostics/System rather than being repeated throughout restaurant workflows.

## Canonical workspaces

- Guests
- Service
- Team
- Kitchen
- Inventory
- Performance
- Executive
- Integrations
- System

Command remains the default operating surface.

## Backend conformance

The cleanup explicitly preserves:
- Command operating picture
- priority ranking
- manager accountability
- outcome verification
- playbook intelligence
- universal provider integrations
- failure/recovery certification
- pilot readiness

No backend engine was deleted merely because its historical UI surface was retired.

## Product rule

Operators see restaurant concepts and actions.
Engineering/release architecture remains behind the product.

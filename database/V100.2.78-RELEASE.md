# V100.2.78 — Time Clock Identity Integrity

## Why this wave exists

Rush-condition testing found that Time Clock timecards, breaks, and correction records used `Date.now()` as the entire unique portion of their IDs. Two records created within the same millisecond could therefore collide.

## Change

The Time Clock service now creates IDs using the existing prefix plus timestamp plus a cryptographically generated UUID fragment. Existing prefixes and downstream ownership references remain unchanged.

## Scope

- timecard identity integrity
- break identity integrity
- correction identity integrity
- regression gate compatibility update for V100.2.76

## Explicitly not changed

- Time Clock operator workflow
- Staffing truth rules
- Scheduling behavior
- payroll
- HR
- polling/timers/observers

# V69.0.0 — Production API Boundary, Abuse Controls & Security Hardening

V69 establishes a production request boundary in front of the Blue Current API.

## Controls

- API-wide request-rate limiting
- tighter authentication/login limiting
- independent webhook limiting
- `429 RATE_LIMITED` with Retry-After and rate-limit metadata
- declared Content-Length rejection before body processing
- streamed body byte limit
- JSON content-type enforcement for mutation bodies
- unsupported HTTP method rejection
- origin allowlisting instead of wildcard API CORS
- production security headers for API and static responses
- CSP, anti-framing, MIME-sniff protection, referrer policy, permissions policy
- sanitized internal 500 responses
- malformed JSON returns 400 rather than a generic server failure

## Origin policy

Allowed by default:
- same-origin/no Origin header
- `bluecurrentco.com`
- subdomains of `bluecurrentco.com`
- localhost/127.0.0.1 development
- temporary `trycloudflare.com` development tunnels

Additional origins may be explicitly configured with:

`BLUE_CURRENT_ALLOWED_ORIGINS`

## Configurable limits

- `BLUE_CURRENT_MAX_BODY_BYTES`
- `BLUE_CURRENT_RATE_WINDOW_MS`
- `BLUE_CURRENT_RATE_LIMIT`
- `BLUE_CURRENT_AUTH_RATE_LIMIT`
- `BLUE_CURRENT_WEBHOOK_RATE_LIMIT`

## Diagnostics

Admin-only:

`GET /api/system/security-boundary`

reports current limits, tracked buckets, blocked requests, payload rejections, origin rejections, media-type rejections, and method rejections.

# V71.50.0 — Schema Mapping, Data Migration Verification & Managed-Store Cutover Framework

V71.50 turns V71's persistence seam into a controlled migration framework without changing the active production driver.

## Deterministic schema mapping

Blue Current can now inspect the active persistence state and generate:
- relational table names
- source-to-column mappings
- inferred scalar types
- primary-key candidates
- tenant/location/time indexes
- planned foreign-key relationships
- per-store source hashes
- a deterministic mapping hash

Admin endpoint:

`GET /api/system/persistence-schema-map`

## Source/backfill verification

Blue Current can generate a deterministic source manifest containing:
- every persisted store
- collection counts
- SHA-256 hashes
- total source records
- whole-manifest hash

Admin endpoint:

`GET /api/system/persistence-source-manifest`

The verification service compares a candidate target snapshot against the source using canonicalized entity ordering, record counts, and SHA-256 values. Ordering differences do not create false failures; content differences do.

## Cutover framework

Admin endpoint:

`GET /api/system/persistence-cutover`
`POST /api/system/persistence-cutover`

Migration phases are persisted and auditable.

A cutover cannot advance into approval/managed-primary phases without:
- verified backfill
- verified shadow reads
- verified dual writes
- explicit human approval

Automatic cutover is always false and rollback remains available.

## What V71.50 does not do

- no PostgreSQL package is installed
- no production data is copied externally
- no dual-write traffic is enabled
- no managed database is made primary
- no automated cutover is permitted

This wave builds the safe migration machinery before any external managed-store move.

# BLUE CURRENT V47.5.0 — HOSPITALITY PERFORMANCE COMMAND

## V47 direction

V46 closed the fine-comb and retirement-control program.

V47 returns primary attention to the operating product: helping restaurant teams identify the highest-value decision, understand why it matters, assign ownership, and act before service performance or margin is lost.

## V47.01 — Cross-Domain Operating Signals

Adds `HospitalityPerformanceService`.

The service composes existing Blue Current intelligence from:
- Restaurant Command Center
- Workforce Intelligence
- Inventory Intelligence
- Guest Intelligence
- Executive Command Center
- reservations / waitlist
- kitchen tickets

No separate synthetic data store is introduced for the opportunity queue.

## V47.02 — Opportunity Generation

Blue Current converts live operating conditions into actionable opportunities across:

- Reservations
- Kitchen
- Labor
- Inventory
- Guests
- Revenue

Examples include:
- pre-assigning booked parties without tables
- reducing long waitlist quotes
- recovering delayed kitchen tickets
- correcting labor coverage / labor-cost gaps
- replenishing critical inventory
- closing food-cost variance
- recovering at-risk guest revenue
- closing revenue pacing gaps

Each opportunity includes:
- category
- title
- why it matters
- next action
- default owner
- severity
- confidence
- estimated dollar impact
- operating-impact label
- source system
- location
- supporting metadata

## V47.03 — Business-Impact Ranking

Opportunities receive an explicit score built from:
- 40% urgency
- 35% estimated impact
- 25% confidence

The queue is sorted from highest to lowest expected operating value.

The score is transparent and advisory; it does not execute the action.

## V47.04 — Human Ownership + Decision Trail

Adds:

`POST /api/hospitality-performance/opportunities/:id/decision`

Supported decisions:
- accepted
- snoozed
- dismissed
- completed

Each decision records:
- organization
- location
- opportunity
- decision
- owner
- note
- actor
- timestamp

The decision is written to the audit ledger and emitted through realtime events.

Policy remains:

- `humanDecisionRequired: true`
- `automaticExecution: false`

## V47.05 — Hospitality Performance Command UI

Adds the new Hospitality Performance Command surface at the top of the operating application.

It shows:
- open opportunity count
- aggregate estimated impact
- high-priority count
- restaurant readiness
- portfolio revenue trend
- ranked opportunity cards
- reason / next action
- owner
- confidence
- estimated impact
- decision history
- action owner / decision note
- Own Action
- Snooze
- Complete

The UI refreshes when:
- authentication is restored
- connectivity returns
- reservation events occur
- inventory decisions occur
- workforce decisions occur

## API

### GET
`/api/hospitality-performance?locationId=<location>`

Returns the ranked operating opportunity queue.

### POST
`/api/hospitality-performance/opportunities/:id/decision`

Records an operator decision.

Both endpoints require authentication. Decision writes require write/admin permission.

## Next V47 milestone

The next V47 wave should turn accepted opportunities into measurable operating outcomes:

- create an action workspace for each accepted opportunity
- define expected outcome / target metric
- capture before / after operating state
- calculate realized vs estimated impact
- measure time-to-resolution
- surface actions that are stalled or not producing the expected result
- feed realized outcomes back into opportunity ranking confidence

That is the next step toward Blue Current not only identifying what matters, but proving what improved.

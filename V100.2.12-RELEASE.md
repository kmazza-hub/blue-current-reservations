# V100.2.12 — Dynamic Table Selection & Assignment Ownership

## Problem fixed
The Host Stand visually allowed a host to select different tables, but the reservation assignment lifecycle remained anchored to the original featured Table 14. This caused the selected-table label and the actual assignment target to diverge.

## Behavior after this repair
- No selected-table detail appears after refresh until a table is explicitly selected.
- The selected table is the authoritative assignment target.
- The CTA always includes the currently selected table number.
- Anthony may be moved from one valid table to another before seating.
- Reserved or seated tables are blocked as conflicting assignment targets.
- The floor map, counts, Arrivals status, guest identity, and seated table use one final table number.
- V100.2.11 auto-collapse behavior is preserved after seating.

## Scope
Client-side Host Stand lifecycle only. No auth, Command shell, server, database, RBAC, reservation creation, waitlist seating, or persistence changes.
